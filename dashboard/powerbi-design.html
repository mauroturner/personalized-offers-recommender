Cómo armarlo en Power BI Desktop

  1. Instale Power BI Desktop (gratuito, solo para Windows) y abra un informe en blanco.
  2. Cree un parámetro de texto llamado CarpetaSalidas con la ruta de outputs\powerbi.
  3. Cree una consulta por tabla publicada (24) con el código de la sección «Power Query»; deje el nombre de la consulta igual al de la tabla. La tabla fact_offer_customer tiene números de cliente: está en outputs\private, no se versiona y no hace falta para este diseño.
  4. En la vista de modelo, cree las 20 relaciones de la tabla «Relaciones»: uno a varios (1:*), filtro único de la dimensión al hecho, todas activas. Los hechos sin clave compartida (fact_choice, fact_experiment, fact_mde, fact_rule) no tienen relación: alimentan sus propios visuales; dim_date es un calendario sin relaciones.
  5. Marque dim_date como tabla de fechas con la columna date.
  6. Cree una tabla vacía llamada _Medidas y agregue en ella las medidas de la sección «Medidas DAX», con su formato.
  7. Cree las 5 páginas a 1280 × 720 px y ubique cada visual según la grilla de 12 columnas por 9 filas; ponga en cada una la leyenda «Sin ofertas reales: el archivo no permite medir el efecto de una oferta».
  8. Guarde el informe como .pbix. Cuando corra el flujo, «Actualizar» vuelve a leer los mismos archivos.
Qué se probó y qué no. Las pruebas del proyecto comprueban que los archivos cumplen el modelo (claves únicas, claves foráneas en su dimensión, relaciones de uno a varios con filtro único) y que cada referencia de cada medida existe; no corren ninguna medida, porque no hay Power BI aquí. Las vistas previas son las cifras de los archivos sin ningún segmentador, no lo que daría el DAX.
Una celda con pocos clientes está oculta. Toda celda que cuenta clientes tiene 10 o más; una más chica aparece como «oculta», y donde un total se publica, un grupo nunca oculta una sola celda, porque el total la daría de vuelta por resta (D30). Ningún archivo tiene números de cliente.

El modelo en estrella

11 dimensiones y 13 hechos publicados. Los hechos de la elección, del A/A, del menor efecto detectable y de las reglas no comparten claves con las dimensiones y alimentan sus propios visuales.

Medidas DAX

Todas van en la tabla _Medidas. Los nombres de las medidas y los textos están en español; las tablas y las columnas, en inglés. Las medidas que leen una tabla con seal_state piden solo las filas selladas.

Clientes en la base

Clientes de la base de las rondas elegidas; una celda con menos clientes que el mínimo está vacía y no suma. Formato: #,0.

Clientes en la base =
SUM ( fact_round_ops[base] )

Reciben oferta

De ellos, los que reciben la lista. Formato: #,0.

Reciben oferta =
SUM ( fact_round_ops[offer] )

Grupo de control

Los que quedaron apartados: su lista se arma y no se entrega. Formato: #,0.

Grupo de control =
SUM ( fact_round_ops[control] )

Listas entregadas

Listas que llegaron al CRM y se leyeron de vuelta iguales. Formato: #,0.

Listas entregadas =
SUM ( fact_round_ops[delivered] )

Parte de reserva

Parte de los productos de las listas que son de la reserva (lo más vendido de 28 días). Formato: 0.0%.

Parte de reserva =
AVERAGE ( fact_round_ops[fallback_share] )

Acierto (hit@10)

hit@10 de la prueba de un método y una variante: la parte de los clientes que compraron con al menos un producto de la lista comprado en la semana. Formato: 0.0%.

Acierto (hit@10) =
CALCULATE ( SELECTEDVALUE ( fact_method_total[hit_rate] ), fact_method_total[seal_state] = "sealed" )

Acierto por ronda

hit@10 de cada ronda: la media de las rondas elegidas, con la configuración sellada. Formato: 0.0%.

Acierto por ronda =
CALCULATE ( AVERAGE ( fact_method_round[hit_rate] ), fact_method_round[seal_state] = "sealed" )

Límite inferior

Límite inferior del intervalo del 95 % del hit@10 (remuestreo por cliente). Formato: 0.0%.

Límite inferior =
CALCULATE ( SELECTEDVALUE ( fact_method_total[ci_low] ), fact_method_total[seal_state] = "sealed" )

Límite superior

Límite superior del intervalo del 95 % del hit@10. Formato: 0.0%.

Límite superior =
CALCULATE ( SELECTEDVALUE ( fact_method_total[ci_high] ), fact_method_total[seal_state] = "sealed" )

Recall (recall@10)

Productos de la lista comprados sobre productos distintos comprados. Formato: 0.0%.

Recall (recall@10) =
CALCULATE ( SELECTEDVALUE ( fact_method_total[recall] ), fact_method_total[seal_state] = "sealed" )

Precisión (precisión@10)

Productos de la lista comprados sobre diez. Formato: 0.0%.

Precisión (precisión@10) =
CALCULATE ( SELECTEDVALUE ( fact_method_total[precision] ), fact_method_total[seal_state] = "sealed" )

NDCG (NDCG@10)

Acierto con descuento por el lugar de la lista. Formato: 0.0%.

NDCG (NDCG@10) =
CALCULATE ( SELECTEDVALUE ( fact_method_total[ndcg] ), fact_method_total[seal_state] = "sealed" )

Cobertura

Productos distintos de las listas de la ronda sobre los comprados en los 365 días anteriores, media de las rondas elegidas. Formato: 0.000.

Cobertura =
CALCULATE ( AVERAGE ( fact_method_round[coverage] ), fact_method_round[seal_state] = "sealed" )

Acierto solo nuevos

hit@10 de la prueba con la lista armada solo con productos que el cliente nunca compró. Formato: 0.0%.

Acierto solo nuevos =
CALCULATE ( SELECTEDVALUE ( fact_method_total[hit_rate] ), fact_method_total[seal_state] = "sealed", fact_method_total[variant_key] = "new_only" )

Acierto por segmento

hit@10 de la prueba de un método y una variante en un segmento; una celda con pocos clientes está vacía. Formato: 0.0%.

Acierto por segmento =
CALCULATE ( SELECTEDVALUE ( fact_segment[hit_rate] ), fact_segment[seal_state] = "sealed" )

Ofrecido a

Clientes del grupo de oferta a los que la lista les puso el producto. Formato: #,0.

Ofrecido a =
SUM ( fact_offer_product[offered_to] )

Comprado por

De ellos, los que lo compraron en la semana; una celda con menos clientes que el mínimo está vacía. Formato: #,0.

Comprado por =
SUM ( fact_offer_product[bought_by] )

Diferencia estandarizada

Diferencia estandarizada de una covariable entre el grupo de oferta y el de control. Formato: 0.000.

Diferencia estandarizada =
CALCULATE ( SELECTEDVALUE ( fact_balance[smd] ), fact_balance[seal_state] = "sealed" )

Mayor diferencia estandarizada

La mayor diferencia estandarizada absoluta de las cinco covariables: lo que mira el criterio C06. Formato: 0.000.

Mayor diferencia estandarizada =
CALCULATE ( MAXX ( fact_balance, ABS ( fact_balance[smd] ) ), fact_balance[seal_state] = "sealed" )

Rechazo del A/A

Parte de los sorteos nuevos del control que la prueba preregistrada rechazó con p menor que 0,05 (debe estar entre 3,1 % y 6,9 %). Formato: 0.0%.

Rechazo del A/A =
CALCULATE ( SELECTEDVALUE ( fact_experiment[calibration_rejection] ), fact_experiment[test] = "preregistered", fact_experiment[seal_state] = "sealed" )

p del A/A

p de la prueba preregistrada con el control sellado, sin ninguna oferta. Formato: 0.000.

p del A/A =
CALCULATE ( SELECTEDVALUE ( fact_experiment[aa_p] ), fact_experiment[test] = "preregistered", fact_experiment[seal_state] = "sealed" )

Menor efecto detectable

Menor diferencia que una operación de este tamaño podría ver: en M1, parte de las semanas con compra; en M2, libras. No es un resultado. Formato: 0.000.

Menor efecto detectable =
CALCULATE ( SELECTEDVALUE ( fact_mde[mde] ), fact_mde[seal_state] = "sealed" )

Veredicto

Veredicto de un criterio con la configuración sellada. Formato: @.

Veredicto =
CALCULATE ( SELECTEDVALUE ( fact_evaluation_summary[verdict_es] ), fact_evaluation_summary[seal_state] = "sealed" )

Última fecha de cálculo

Instante de cálculo de la última corrida terminada bien. Formato: yyyy-mm-dd hh:mm.

Última fecha de cálculo =
CALCULATE ( MAX ( dim_pipeline_run[as_of] ), dim_pipeline_run[status] = "ok" )

Reglas bloqueantes fallidas

Resultados de reglas bloqueantes que fallaron, en las corridas cargadas. Formato: #,0.

Reglas bloqueantes fallidas =
CALCULATE ( COUNTROWS ( fact_validation ), fact_validation[severity] = "bloqueante", fact_validation[status] = "falla" )
